# Мой город (DniesterCity) · версия 0.3

Единое окно коммунальных услуг ПМР: веб-приложение для жителя и диспетчера, сервер Node.js, PostgreSQL и Telegram-бот.

**Демонстрация:** https://moy-gorod-utilities-kirill.primekid15.chatgpt.site — приватный интерфейс с учебными данными. Изменения сохраняются в браузере. Настоящий сервер, бот и PostgreSQL размещаются отдельно: статический хостинг Sites их не исполняет.

## Что нового в 0.3

- **Дизайн в стиле DniesterWorks:** светлая бело-синяя тема по умолчанию, полноценная тёмная тема на токенах (без инверсии), шрифты Inter + Montserrat, свечение фона, карточки и поля на одной системе цветов.
- **Анимации framer-motion:** вход страниц, модальные окна (на телефоне — шторкой снизу), появление и подъём карточек, раскрытие списков; всё отключается системным «уменьшить движение».
- **Свои выпадающие списки** вместо системных: клавиатура, ARIA, раскрытие вверх у края экрана.
- **Карты:** пины с иконками услуг, пульс у текущих работ, подсказки и кнопки в цветах темы, «Где я», подгонка масштаба, легенда, тёмные тайлы. Исправлен сброс масштаба при выборе точки.
- **Новый раздел «Транспорт»:** маршрутки (ближайший рейс по времени ПМР, линия и остановки на карте) и такси (оценка цены по маршруту, кто работает сейчас, звонок).
- **Feature-Sliced Design** во фронтенде, псевдоним `@/`.
- **Prisma 7.10** вместо сырых запросов `pg`: схема и миграции в `prisma/`, тесты на PGlite с теми же миграциями.
- **Бесплатный хостинг на Render** одним Blueprint (`render.yaml`): сайт + API + бот (webhook) + Postgres.
- Документы: [CJM](docs/CJM.md) ([визуальная версия](docs/cjm.html)), [QA-отчёт](docs/QA-REPORT.md), [миграции](docs/MIGRATIONS.md), [руководство](docs/MANUAL.md), [деплой на Render](docs/DEPLOY-RENDER.md).

## Журнал разработки 0.3 — по шагам

Каждый шаг — отдельный коммит; после каждого прогонялись `tsc`, юнит-тесты и e2e.

1. **Структура репозитория.** Лишняя обёртка убрана: приложение лежит в `dniester-city/`, в корне — `render.yaml`.
2. **Исходная проверка.** `npm ci`, типы, тесты. Один тест падал: проверял весенний перевод часов на 03:30, а в Молдове пропадает 02:00–02:59. Тест исправлен (код дат был верным).
3. **FSD.** Файлы разложены по слоям `app / pages / widgets / features / entities / shared` скриптом, который переписал все импорты; общий UI отделён от карточек домена, экспорт CSV вынесен в `features/export-readings`, у страниц появились публичные `index.ts`. Правило слоёв проверено поиском «импортов вверх».
4. **Токены и темы.** `src/app/styles/tokens.css` — один набор токенов для светлой и тёмной темы и трёх акцентов. Около 200 зашитых цветов в CSS заменены токенами автоматически (по свойству и светлоте цвета), хак `filter: invert()` удалён. Слой `dw.css` переносит визуальный язык DniesterWorks. Проверено скриншотами светлой/тёмной темы на ПК и телефоне.
5. **Select.** `shared/ui/Select.tsx` повторяет API нативного `<select>`, поэтому заменил все 13 списков без переписывания логики форм (скрытое поле `name` для FormData). e2e переведены на хелпер `e2e/select.ts`. Найден и исправлен баг «клик по пункту внутри `<label>` снова открывает список». Подняты контрасты статусов до WCAG AA (тест axe).
6. **Анимации.** `MotionConfig reducedMotion="user"`, переходы страниц и модалок на framer-motion, CSS-появление карточек со ступенчатой задержкой.
7. **Карты.** Общий модуль `shared/lib/map.ts` (карта, пины, «Где я»), карты больше не пересоздаются при каждом изменении. Тайлы CARTO теперь требуют ключ, поэтому OSM + затемнение только слоя тайлов в тёмной теме.
8. **Транспорт.** `entities/transport` (данные и чистые функции с юнит-тестом), `widgets/map/RouteMap`, `pages/transport`, пункт меню; e2e-сценарий. Заодно починено обрезание пунктов верхнего меню на ноутбуках.
9. **Prisma 7.10.** `schema.prisma` повторяет прежнюю схему один в один (snake_case), `0_init` сгенерирован `prisma migrate diff` и дополнен CHECK/GIN/индексом по jsonb, перенос данных v0.1 — отдельная миграция. Сервер переведён на Prisma Client + `@prisma/adapter-pg`; jsonb-операторы и блокировки — типобезопасным `$queryRaw`. Тесты переведены на `pglite-prisma-adapter`. Подробно — [MIGRATIONS.md](docs/MIGRATIONS.md).
10. **Бот для бесплатного Render.** Фоновые воркеры на free платные, поэтому добавлен `BOT_MODE=webhook`: бот и очередь уведомлений работают в процессе API, вебхук защищён секретом (тест). Обычный процесс `npm run bot` остался для Docker/VPS.
11. **Документы и QA.** README, CJM (Markdown + HTML), QA-отчёт, миграции, руководство, гайд по Render.

## Что умеет продукт

- Восемь направлений: электричество, холодная и горячая вода, газ, отопление, канализация, вывоз отходов и обслуживание дома.
- Несколько адресов и отдельные категории уведомлений для каждого дома.
- Поиск, фильтры и архив событий; источник, сроки, история изменений и честный статус «Срок неизвестен».
- События на несколько домов, черновики без рассылки, проверка и предпросмотр перед публикацией. В серверном режиме предпросмотр считает подписчиков без раскрытия их данных.
- Несколько счётчиков одной услуги с заводским номером, лицевым счётом и независимой историей. Проверка периода, дубликатов и уменьшения значения; график расхода и экспорт CSV для Excel.
- Обращения с приоритетом, историей, последовательными статусами и повторным открытием после выполнения.
- Панель диспетчера с фильтрами очереди, управлением событиями и графиками. Администратор редактирует организации и зоны ответственности с проверкой пересечений.
- Мобильная нижняя навигация, управление диалогом с клавиатуры, увеличение текста и локальные шрифты. Карта и дополнительные экраны загружаются по требованию.
- «Режим защиты»: четыре действия создают помеченные учебные записи и показывают путь от черновика до принятой заявки. Счётчики отражают текущее состояние демо, не статистику внедрения.

**Официальное принятие показаний поставщиком, начисления и платежи не имитируются.** Статус «Сохранено в сервисе» не означает передачу в учётную систему организации.

## Быстро запустить демо

Нужен Node.js 22.12+; сборка проверена на Node.js 24.

```powershell
npm ci
npm run db:generate   # Prisma Client (нужен и для тестов, и для сервера)
npm run dev
```

Открыть http://127.0.0.1:5173. Без `.env` включается деморежим. Кнопка «Панель диспетчера» переключает учебную роль только в браузере. Начальные данные: адрес Тирасполь, ул. Ленина, 18; события, счётчики и учебное обращение. В настройках можно сбросить демо.

## Запустить серверный пилот

1. Скопировать `.env.example` в `.env` и заполнить `BOT_TOKEN`, `MINI_APP_URL`, `DATABASE_URL` и случайный `SESSION_SECRET` длиной от 32 символов. Вне локального теста заменить пароль БД.
2. Установить `VITE_DATA_MODE=server`. При размещении интерфейса и API на одном origin оставить `VITE_API_URL` пустым.
3. Запустить Docker Desktop и выполнить:

```powershell
docker compose up -d db
npm run db:migrate      # prisma migrate deploy
npm run build
npm run server:prod
```

4. В другом терминале: `node build/server/bot.mjs` (или `BOT_MODE=webhook` + `PUBLIC_URL`, тогда бот работает внутри API).

База, созданная версией 0.2 (до Prisma): один раз `npm run db:baseline`, затем `npm run db:migrate` — см. [MIGRATIONS.md](docs/MIGRATIONS.md).

**Бесплатный хостинг:** [пошагово на Render](docs/DEPLOY-RENDER.md) — один Blueprint поднимает сайт, API, бота и базу.
5. Настроить HTTPS reverse proxy к `127.0.0.1:3001`, указать этот публичный URL в `MINI_APP_URL` и настройках Telegram-бота. Открывать приложение кнопкой бота. Обычный переход без подписанных данных Telegram не авторизует пользователя.

При первом входе создаётся пустой личный кабинет. Демо-события в серверную базу не загружаются. Пользователь добавляет адрес; подписка не является подтверждением собственности и не открывает чужие показания или обращения.

`ADMIN_TELEGRAM_IDS` задаёт администраторов **при создании** пользователей. Изменение и отзыв существующей роли выполняются оператором в БД. Роль проверяется при каждом запросе, поэтому прежний токен сессии не сохраняет отозванный доступ.

Для разработки одновременно запускать `npm run dev` и `npm run server`: Vite проксирует `/api` на порт 3001.

### Контейнеры приложения и бота

В `compose.yaml` предусмотрен отдельный профиль `pilot`. После заполнения `.env`:

```powershell
docker compose --profile pilot build
docker compose up -d db
docker compose --profile pilot run --rm migrate
docker compose --profile pilot up -d app bot
```

Контейнерная сборка включает серверный режим интерфейса. База хранится в volume `city_data`, приложение доступно только на локальном порту 3001; внешний доступ организуется через HTTPS proxy. Dockerfile подготовлен, но в этом рабочем окружении Docker daemon недоступен, поэтому образ здесь не собирался.

## Организации и графики

Администратор может управлять ими в панели. Для первоначальной настройки есть также операторский CLI:

```powershell
npm run provision -- provision.example.json
```

Сначала заменить учебные значения в собственном конфигурационном файле. Для назначения диспетчера после его первого Telegram-входа добавить в `dispatchers` объект `{"telegramId":123456789,"organizationId":"water-pilot"}`. При контейнерном запуске использовать скомпилированный `build/server/provision.mjs` и передать файл конфигурации внутрь контейнера.

Кабинет организации и интеграция с её учётной системой — разные этапы. Флаг подключения кабинета не выдаёт сохранённые показания за официально принятые.

## Проверки и сборка

```powershell
npm test
npm run build
npm run dev
npm run test:e2e
```

- Проверки типов, в том числе неиспользуемого кода; версии зависимостей зафиксированы.
- Доменные тесты показаний, отдельных счётчиков, черновиков, версий и зон организаций.
- SQL-тесты на PGlite через Prisma и те же файлы миграций: права, адресные уведомления, миграция истории версии 0.1.
- Webhook бота: принимает только свой секрет.
- Транспорт: ближайший рейс, оценка такси, ночные часы работы.
- HTTP-тест с подписанными тестовыми данными Telegram: вход, отзыв роли, запрет чужого счётчика, предварительный расчёт подписчиков и повтор запроса без дублирования.
- Тест очереди с подставным отправителем: аренда задания, сетевой вызов после транзакции, `retry_after` и постоянная ошибка получателя.
- Браузерные сценарии жителя и диспетчера, режим защиты, мобильная компоновка, клавиатура и автоматическая проверка WCAG AA главного экрана и формы показаний.

`npm run build` создаёт `dist/` и готовые Node.js-модули в `build/server/`. Для запуска готового API не нужен tsx: `npm run server:prod`. Команда `npm run format` форматирует исходники. Скриншоты и результаты браузерных тестов находятся в `.local/` и не входят в репозиторий.

Тесты браузера используют установленный Chrome в Windows. На другой системе поменять `executablePath` в `playwright.config.ts` либо установить браузер Playwright и удалить этот параметр.

## Что требуется для реального внедрения

Токен бота, доступный PostgreSQL, HTTPS-сервер, согласованные ответственные сотрудники и проверенные источники. Настоящая отправка Telegram и вход реального пользователя без токена не проверены. SQL/HTTP проверены через Prisma на встроенном PostgreSQL-движке (PGlite); конкурентные процессы и нагрузка на отдельном PostgreSQL ещё требуют испытания.

Следующие этапы: полноценный адресный классификатор и реальные координаты домов, подтверждённые аварийные контакты, фотографии с закрытым хранилищем, замена/обнуление счётчиков и тарифные зоны, черновики из парсеров официальных источников, официальный приём показаний, начисления и платежи. Карта текущего демо использует условные точки; это явно обозначено.

Перед большим запуском нужны резервные копии, политика хранения данных, мониторинг очереди и распределённое ограничение запросов для нескольких серверов. Уведомления имеют уникальные задания, но при потере подтверждения Telegram отправка может повториться — гарантия at-least-once.
